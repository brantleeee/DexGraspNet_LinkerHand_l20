# v2原网格生成穿透失败复盘（2026-11-18）

**本批不能作为合格抓取使用。上一轮把“原网格查询和分指槽接通”作为可进入6000步生成的依据，验收不足，暂停推荐v2长生成命令。五指分组机制正确执行，但防穿透没有形成可靠闭环。**

## 现象和身份核对

批次`l20_v2_clean_drill_20261117_174021`确实完成32候选/6000步，raw-mesh、grouped5、403点、12根部豁免、scale1。32个候选均为五指各1槽、点号唯一，问题不能解释成新选项未加载。

然而静态阈值通过数为**0/32**。E_pen最小约0.003147m，已经高于0.001m的既有阈值。能量排名第1（原下标13）的E_pen约0.010000m，也未通过。这里E_pen是单方向多个采样点的内部距离求和，不是最大穿透深度。

原导出策略会在没有合格候选时仍展示能量最低的前16；Canvas排名不能当作合格筛选。本次不能以“生成结束”“排名第一”或“点已贴近”验收。

## 问题分析

### 1. 穿透目标只有一个方向

`energy.py`只计算`object_surface_points → hand.cal_distance`。它没有反向计算`hand_surface_points → object`。

手指整个进入物体时，物体外表面仍可能没有任何采样点进入细薄/中空手指的实体区域。因此单向项可以漏掉严重手入物体，即使距离符号完全正确也存在这个缺口。

新增反例测试：大封闭立方体包含小封闭立方体，大物体表面点没有进入小物体，旧方向罚为0；小物体顶点全部在大物体内部，反向罚明显为正。这是算法覆盖不足，不是调权重就能根除。

原凸包可能意外提供更保守的阻挡，但改回凸包不能被称为原非凸几何的正确解决方案。

### 2. 最近三角面法向不是全局包含判定

TorchSDF CUDA源码取最近三角面的`dot(p-closest, face_normal)`决定符号，没有做全局射线/绕数包含判定。开放面、棱边、多壳装配会出现不可靠分类。

本轮对闭合link在原样保存的2000物体采样点上作射线对照：候选18中middle_distal有1个射线判内部、CUDA判外的点，距原面约0.459mm；候选5另有2个相反分类例。闭合网格射线自身也有多部件/边界限制，不能将这些数量外推为整个模型误判率，更不能把厘米级失败全部归因于这几个符号例。

包围盒外强制外侧只排除了不可能的远场内部，**不能修复包围盒内部符号或反向漏检**。我上一轮已经知道开放网格风险，却没有先建立包含物体/已知穿透的正向回归，仍交付长生成命令，这是验证不足。

### 3. 随机有限采样和软罚项没有硬验收护栏

每个候选仅使用2000个物体表面点，薄壁交叉或小区域可漏采。有限权重也允许优化器用穿透换取其他项下降。没有“严重穿透直接拒绝”的全手几何准入，也没有只从通过者导出可用参考。

### 4. 五指参与不等于无碰撞

本批32个结果分组全部正确，证明该约束生效。它要求五指都有接近目标，但若碰撞保护失效，仍可把手指拉到物体另一侧或内部。不能因槽分组正确就推断生成结果正确，也没有证据把本轮全部失败归为分组采样实现错误。

## 同采样复算与不确定性

使用保存的`object_surface_points.npy`复算原下标13/5/18：前两者与保存E_pen一致；18从约.003147变为.014908，尚未定位是否由保存姿态的Euler/6D重构、棱边符号切换或其他数值因素引起。已记录不一致，没有继续使用断言中断审计或将其隐去；不能据此直接断言优化器拒绝状态恢复错误。

因此本轮确认的是显著独立反向穿透、单向覆盖缺口和符号风险，不声称已找出每个分数变化的唯一根因。

## 本轮处理和后续验收

本轮新增冻结结果审计脚本和单向包含反例测试；未修改生成核心、重跑优化、停止进程或覆盖旧位姿。已在v2文档撤回长生成推荐。

下一修复版本必须先做到：

1. 为双方明确可靠的非凸碰撞实体/包含定义；开放手部link单独处理，不能仅原面套旧伪法向符号。
2. 加入双向穿透或等价完整的表面交叉+实体包含检查；不能只修物体入手方向。
3. 对已知无碰撞、部分交叉、整根手指被包含、反向包含、近切点建立回归，并验证穿透梯度能把物体/手指推向外侧。
4. 严重穿透采用准入/拒绝机制，诊断排名与可用参考分开展示；没有通过者必须明确返回无合格抓取。
5. 先在本次3个真实失败构型证明检出，再小批短优化检查错误不恶化，最后才6000步和600g物理验证。

这些是下一版验收条件，**本轮没有宣称已实现或修好**。
