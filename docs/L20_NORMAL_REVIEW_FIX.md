# 核查页法向诊断与投影查询修正（2026-11-16）

用户发现四条线视觉上像接触面切线。核查结论：叉乘及面索引对应未发现错误，但单个最近微面不等于宏观夹持面；最近投影又受到米制微小三角形容差影响，旧页未充分展示选面，因此不适合直接据此判定接触法向。

## 证据

对所选面两条边e1/e2独立叉乘，得到的单位法向与原face_normals一致，法向与两边归一化点积约1e-17。因此这些向量不是其所选三角形的切向。

但是原Trimesh closest_point实现用固定tol.zero判断RTCD边域，其中vc/vb/va为长度四次方量。米制0.1–0.5mm小面片的这些值会小到被误判为边域。用毫米单位查询与米制原查询得到不同投影，而逐三角形归一化后结果与毫米/更大单位复核一致。原选面ID在这四点没有变，投影位置和实际棱边识别却发生了变化。

|---|---:|---:|---:|---|---|
|211|5819|.214585|.196106|棱边|90.64°|

|228|5657|.175962|.175962|棱边|77.53°|

因此211/228/231只取一个面的法向会漏掉尖锐棱边另一侧，所取面法向可能看起来沿相邻面。不能把单面向量作为唯一物理接触法向。219位于面内部，数学法向与所选小面垂直；仍需通过高亮确认该小面是不是希望使用的宏观指腹面，不能仅凭它与外观主体表面的关系自动改方向。

四个接触候选本身也不在原始手表面上，偏离约.176–.196mm。本次只纠正查询和显示，没有移动候选点、改STL或重写接触点文件。若后续重新定义接触点位置，必须新版本重新枚举目标，不能沿用旧能量缓存。

## 修正

新增robust_surface_query.py：逐三角形平移/归一化后计算最近点，再还原米制，避免依赖全局长度单位的边域误判。C点外侧查询也使用此最近距离；包含查询在统一毫米数值尺度上进行，原物体几何不缩放、不改位姿，只换计算坐标尺度。

保留已有局部法向诊断功能，新页显式显示：红色所选面及法向箭头、绿色切向、青色邻面、黑色候选点到最近表面连线。normal_diagnostics.json记录三角顶点、边点积、重心坐标和邻面角度。不是将法向硬转90度，也没有将最近距离向量或平滑法向冒充单面法向。
